# 网关与云端方案

## 调研范围

针对采集网关和云端的数据管理进行方案比较。数据类型为分钟级传感器模拟量和小时级图片；现场网关需在云端或 4G 网络暂时不可用时继续采集并缓存数据。

本文基于项目现有调研资料整理，云资源现状和价格尚未核验。

## 术语

| NM | name | 名称 | 说明 |
| :-: | :--: | :-: | :-: |
| 现场 | Field side | 现场侧 | PLC、相机、采集网关和 4G 通信设备所在的设备现场。 |
| 网关 | Gateway | 采集网关 | 位于现场、负责采集编排、本地存储、断网缓存和云端上传的工控机。 |
| PLC | Programmable Logic Controller | 可编程逻辑控制器 | 负责现场传感器采集、机械臂动作、光源控制和安全互锁的控制设备。 |
| Outbox | Transactional outbox | 待发送箱 | 将业务数据和待上传事件先写入本地数据库，再由独立上传器异步发送到云端的可靠队列模式。 |
| ECS | Elastic Compute Service | 弹性计算服务 | 阿里云提供的云服务器计算资源，用于运行本项目业务 API、管理服务或后台任务。 |
| API | Application Programming Interface | 应用程序接口 | 不同软件之间交换数据和调用功能的约定；本文主要指网关与云端之间的业务 HTTPS API。 |
| OSS | Object Storage Service | 对象存储服务 | 用于保存 JPEG 等文件对象的云存储服务；图片索引和业务关联仍保存在数据库中。 |
| 数据库 | Database | 数据库 | 保存测量记录、样本关系、图片索引、上传状态和审计信息的结构化数据存储。 |
| SQLite | SQLite | SQLite 数据库 | 部署在现场网关上的轻量级嵌入式数据库，用于保存本地元数据和 outbox 状态。 |
| Modbus TCP | Modbus over TCP | 基于 TCP 的 Modbus | 网关与 PLC 之间使用的现场通信协议。 |
| GigE Vision | Gigabit Ethernet Vision | 千兆以太网视觉协议 | 相机通过千兆以太网向网关传输图像帧的工业视觉通信标准。 |
| MVS | Machine Vision Software | 海康机器视觉软件 SDK | 海康相机的软件开发工具包；本文选用 MVS 5.1.1 ARM64 版本进行设备控制和取帧。 |
| JPEG | Joint Photographic Experts Group | JPEG 图像 | 本项目用于云端上传和本地缓存的图像编码格式。 |
| SHA-256 | Secure Hash Algorithm 256-bit | SHA-256 校验和 | 用于校验本地文件、上传对象和云端记录是否对应同一份图像数据的摘要算法。 |
| WAL | Write-Ahead Logging | 预写式日志 | SQLite 的日志模式，使读写并发和事务恢复更适合现场采集；仍需正确配置同步和备份。 |
| 幂等 | Idempotency | 幂等处理 | 同一业务请求因超时或重试被提交多次时，只产生一个业务结果，不创建重复记录。 |
| 预签名 URL | Presigned URL | 预签名链接 | 云端临时签发的、限定对象和有效期的上传或下载地址，避免设备持有长期 OSS 密钥。 |

## API 概念对比

这四个概念并非同一层级：**HTTP API 描述接口的通信方式；ECS API、ECS 业务 API、托管 API 描述接口所管理的对象、承载位置或运维模式。** 因此，ECS 业务 API 和托管 API 通常都可以是 HTTP API。

| 对比维度 | HTTP API | ECS API（阿里云 ECS 管理 API） | ECS 业务 API（ECS 自定义 API） | 托管 API |
|---|---|---|---|---|
| 概念层级 | 通信接口风格/协议形式 | 云资源管理接口 | 项目业务接口及其部署方式 | API 入口或业务后端的托管/运行方式，具体含义需指明产品 |
| 主要管理对象 | 由 API 定义，通常是业务资源 | ECS 实例、镜像、磁盘、安全组等云资源 | 项目中的设备、测量、样本、图片和用户操作 | 可能是 API 流量入口，也可能是托管业务代码；视具体平台而定 |
| 提供方 | 接口由服务开发者设计；HTTP 是通用 Web 通信协议 | 阿里云 | 项目团队开发和维护 | 云平台提供部分运行、路由或运维能力；业务规则通常由项目团队定义 |
| 运行位置 | 任意可提供 HTTP 服务的服务器或平台 | 阿里云控制面，调用方通过云 API 访问 | 通常运行在 ECS 实例上 | 可能运行在 API 网关、托管容器、Serverless 等平台 |
| 典型调用方 | 浏览器、网关、其他服务 | 云平台控制台、云资源自动化工具 | 采集网关、Web 管理端、后台任务 | 网关/客户端调用托管入口，入口再转发至后端；或客户端调用托管业务后端 |
| 典型操作 | `GET` 查询、`POST` 创建/提交、`PUT` 更新、`DELETE` 删除 | 创建/启动/停止/释放实例、管理云资源 | 上传测量、申请图片上传授权、确认上传、查询测量 | 路由请求、鉴权、限流、调用托管函数或容器服务 |
| 认证授权 | 由接口设计，可使用 TLS、令牌、签名等 | 阿里云账号/角色与云 API 签名授权 | 项目设备身份、用户身份、业务角色和对象级权限 | 云平台入口权限与后端业务权限；通常两层都要考虑 |
| 业务逻辑归属 | 不由 HTTP 形式决定 | 不承载本项目测量业务逻辑 | 项目团队实现，例如数据校验、幂等、测量入库 | 平台托管不自动等于业务逻辑已实现；后端仍需实现业务规则 |
| 运维责任 | 由接口所在服务的运维方承担 | 阿里云运行控制面，用户管理调用权限和云资源配置 | 项目团队负责应用部署、升级、监控、容量与恢复 | 云平台承担约定范围内的底层能力；项目团队仍负责业务配置、权限、数据和恢复目标 |
| 本项目是否直接使用 | **是**，网关以 HTTPS 调用业务接口 | **通常否**，网关不应拥有创建/停止 ECS 的权限 | **是**，这是网关上传数据和申请图片授权的接口 | 仅在选用具体托管平台后使用，需明确托管的是 API 网关还是 API 后端 |
| 关键误区 | HTTP API 不等于某种云服务 | ECS API 不等于“运行在 ECS 上的 API” | ECS 只提供计算资源，不会自动生成项目 API | “托管 API”不是足够精确的产品名称，须说明托管边界 |

### 关系示意

```text
采集网关
  └── HTTPS（HTTP API + TLS）调用项目业务 API
       ├── 方案一：业务 API 由项目团队部署在 ECS
       └── 方案二：业务 API 部署在托管容器/Serverless 等平台
             └── 可选 API 网关：统一入口、路由、限流或认证

云平台运维工具
  └── 调用阿里云 ECS 管理 API 管理 ECS 资源
      （与现场网关的测量数据上传链路分离）
```

### 命名建议

- 将“**ECS API**”限定用于“阿里云 ECS 管理 API”，避免与业务接口混淆。
- 将项目上传接口称为“**项目业务 HTTP API**”；如部署在 ECS 上，写作“**部署在 ECS 上的项目业务 API**”或“**ECS 自定义业务 API**”。
- 使用“**托管 API**”时注明具体指“托管 API 网关”还是“托管 API 后端/计算平台”，并列明平台承担的运维范围。

## 2. 现场方案

现场侧采用“**SQLite 保存元数据，图像文件保存图片，outbox 管理云端同步**”的组合。三者分别解决不同问题，不将所有数据放入 SQLite，也不让上传程序直接扫描图片目录判断业务状态。

```text
PLC 传感器数据 ─┐
                ├─> SQLite：测量值、样本关系、状态和校验信息
相机图像 ───────┘       │
                        └─> outbox：待上传事件、重试状态和错误记录

相机图像 ──> 本地 JPEG 文件 ──> outbox 异步同步
SQLite 元数据 ─────────────────> outbox 异步同步
```

### 组件职责

| 组件 | 保存内容 | 主要职责 | 不负责的内容 |
|---|---|---|---|
| **SQLite** | 测量记录、图片元数据、样本关系、设备状态、上传状态 | 提供本地事务、查询、恢复和队列状态 | 不保存大尺寸 JPEG 二进制，不直接承担云端长期存储 |
| **图像文件** | 相机采集后编码的 JPEG | 保存实际图像内容，支持哈希校验和上传 | 不单独表示业务上传状态，不由文件名替代数据库记录 |
| **outbox** | 待上传事件及其状态 | 在断网、超时、进程重启后继续上传，并控制重试 | 不保证服务端不重复接收，必须依赖云端幂等 |

### 推荐目录

```text
/data/collector/
├── db/
│   └── collector.sqlite3
├── images/YYYY/MM/DD/<sample_id>/
│   ├── <image_id>.jpg
│   └── <image_id>.jpg.tmp
├── manifests/YYYY/MM/DD/<sample_id>/
└── logs/
```

SQLite 数据库、WAL 文件和图像目录应放在现场网关的本地可靠文件系统上，不放在网络文件系统上。图像文件和 SQLite 记录之间不是一个跨资源原子事务，因此必须通过启动扫描和一致性检查处理异常中断。

### 传感器写入

```text
读取 PLC
  -> 校验寄存器和工程值范围
  -> 生成 measurement_id
  -> 一个 SQLite 事务：写 measurement + 写 outbox(pending)
  -> 提交成功：本地采集完成
  -> 上传器异步发送
  -> 云端确认后：outbox = uploaded
```

传感器采集不等待云端响应。SQLite 事务提交失败时，该次采集标记为本地失败并告警，不能只在内存中保留数据。

SQLite 建议启用 WAL、外键和合理的忙等待。需要断电后保留已提交事务时采用 `synchronous=FULL`，并验证存储介质正确执行同步写入；WAL 本身不保证断电持久性，`NORMAL` 模式可能丢失最近已提交事务。备份使用 SQLite 支持的一致性备份方式，不能只复制正在写入的数据库主文件。

### 数据实体

| 实体 | 用途 | 建议关键字段 |
|---|---|---|
| `sample` | 样本/试验上下文 | `sample_id`、`device_id`、开始/结束时间、业务标签、状态 |
| `measurement` | 单次传感器采样 | `measurement_id`、`sample_id`、采集 UTC 时间、工程值、PLC 原始值、质量状态 |
| `image` | 单张图片元数据 | `image_id`、`sample_id`、本地路径、采集时间、大小、宽高、编码格式、SHA-256 |
| `outbox` | 待同步事件 | `event_id`、实体类型/ID、状态、尝试次数、下次重试时间、错误摘要 |
| `device_state` | 网关状态快照 | PLC/相机/4G 状态、磁盘占用、时钟状态、最近采集/同步时间 |

ID 使用全局唯一值（如 UUIDv4/UUIDv7），同一 ID 用作云端幂等键。记录 UTC 时间用于跨系统对账，并用单调时钟计算本机超时；若 PLC 不提供可信采样时间，应注明为网关读取时间。

### 图像写入

```text
相机取帧
  -> 校验帧完整性、尺寸、像素格式和帧号
  -> Bayer 转 JPEG
  -> 写入 .jpg.tmp
  -> flush/fsync 文件
  -> 原子改名为 .jpg，并同步父目录
  -> 计算 JPEG 大小和 SHA-256
  -> SQLite 事务：写 image + 写 outbox(pending)
  -> 本地图像保存完成
```

必须先完成本地图像落盘，再执行云端上传。上传失败不影响已完成的本地保存；只有云端完成接口确认对象存在、大小和 SHA-256 正确后，才把 outbox 标记为 `uploaded`。

### outbox 状态

```text
pending -> uploading -> uploaded
              │
              ├─ 可重试错误 -> retry_wait -> uploading
              └─ 永久错误   -> dead_letter
```

建议字段包括：`event_id`、`entity_type`、`entity_id`、`payload_version`、`status`、`attempt_count`、`next_retry_at`、`last_error`、`created_at`、`updated_at`。传感器和图像使用独立队列或优先级，传感器数据优先，图像首版并发数为 1。

- `pending`：本地事务已提交，尚未开始发送。
- `uploading`：上传器已领取；网关重启后需要回退到可重试状态。
- `retry_wait`：网络超时、DNS 失败、HTTP 408、429 或 5xx 等暂时性错误等待退避。
- `uploaded`：已收到云端持久化确认，可按缓存策略清理本地文件。
- `dead_letter`：数据格式错误、业务 ID 内容冲突、确认文件损坏等无法自动恢复的问题，需保留原始记录并告警。认证失败时先尝试约定的令牌刷新流程；凭据被撤销或权限不足时暂停相关上传并告警，修复凭据后允许重新入队。校验失败应先区分传输错误与本地文件损坏，不能一律判定为永久错误。

### 上传调度与限流

上传器只消费已提交的 outbox 事件，传感器小批量优先，图片首版并发数为 1。失败重试采用指数退避和随机抖动，并设置最大退避间隔；持续监控待传字节数、最老事件年龄、连续失败次数和预计清空时间。恢复联网后限制补传速率，避免积压图片挤占实时小数据。只有服务端明确支持并验证上传会话恢复时才使用断点续传，否则采用完整文件幂等重传。

### 恢复与校验

网关启动时执行以下检查：

1. 将遗留的 `uploading` 事件恢复为 `retry_wait` 或 `pending`，避免进程崩溃导致队列永久卡住。
2. 扫描 `.tmp` 文件；完整性无法确认的临时文件移入隔离目录并告警，不能直接当作有效图片上传。
3. 扫描已有 JPEG 是否存在对应的 SQLite `image` 记录；缺少记录的文件不自动删除，先生成诊断项并人工处理或按明确规则恢复。
4. 检查数据库记录指向的图像文件是否存在；缺失文件的事件进入 `dead_letter`，并记录缺失原因。
5. 校验已排队图像的文件大小和 SHA-256；发生变化时禁止上传并告警。

### 容量与清理

本地容量按最长离线时间计算：

```text
最低缓存空间
  >= 最长离线天数 ×（每日 JPEG 最大产生量 + 每日测量元数据）
  + SQLite/WAL
  + 日志、临时文件和重试空间
  + 安全余量
```

当前基线为每天 96 条传感器测量和 12 张图片。图片应使用现场实测平均值、P95 和最大值核算；建议至少预留 2 天产生量。磁盘达到高水位时先告警并禁止新的图像任务，不能删除未收到云端确认的数据。已确认上传的图片按照本地缓存保留窗口清理，数据库中的本地记录是否清理应与审计和追溯要求单独确定。

### 方案边界

该方案保证的是“**先在现场可靠保存，再异步同步云端**”，不是云端实时写入，也不是跨设备分布式事务。它依赖以下前提：本地存储介质可靠、数据库事务正确提交、图像哈希可校验、云端接口支持幂等，以及现场有足够的离线缓存空间。

## 3. 云端方案

### 3.1 云端组件

云端按“业务接入与校验、结构化数据管理、图片对象存储”分层。本文所说的 ECS API 是**部署在 ECS 上的项目业务 API**，不是阿里云 ECS 管理实例的 API。

| 组件 | 定位 | 本项目保存/处理内容 | 主要优点 | 主要代价与边界 |
|---|---|---|---|---|
| **ECS** | 云端计算资源 | 运行项目业务 API、管理页面和轻量后台任务 | 部署灵活，可复用现有 ECS，运行环境和网络可控 | ECS 本身不提供业务接口；需自行负责系统更新、应用发布、监控、备份和可用性设计 |
| **业务 API** | 网关与云端之间的业务入口 | 设备认证、测量校验与幂等接收、图片登记、预签名 URL、上传完成校验、查询与审计 | 集中执行业务规则和权限校验；避免设备持有数据库或 OSS 长期凭据 | 需自行开发和维护；需要限流、鉴权、版本兼容、审计、故障恢复；图片不宜经 API 服务器转发 |
| **数据库** | 结构化业务数据存储 | 设备、样本、测量、图片索引、上传状态和审计信息 | 支持按设备、样本、时间范围筛选和关联查询；可用唯一约束实现幂等 | 需管理备份、容量、权限和恢复；自建与托管的维护责任不同；不建议存 JPEG 二进制 |
| **OSS** | 对象存储 | JPEG 图片及其对象元数据 | 适合大文件存储、对象级授权和生命周期管理；网关可用预签名 URL 直传 | 不理解测量/样本的业务关联；需控制 Bucket 权限、对象键、保留期和删除保护；持久性不等于备份 |

#### API 流程

1. **测量数据：** 网关批量提交测量和稳定的 `measurement_id`；API 校验设备权限、字段和单位，通过幂等逻辑写入数据库并返回逐条结果。
2. **图片登记：** 网关提交 `image_id`、`sample_id`、文件大小、SHA-256 和格式；API 校验设备权限，在数据库创建待上传索引，并生成限定对象键、权限和有效期的预签名 URL。
3. **图片上传：** 网关使用预签名 URL 直接把 JPEG 上传 OSS，不经过 ECS API 服务器转发。
4. **完成确认：** 网关通知 API 上传完成；API 检查 OSS 对象存在、大小和约定的校验值，确认后更新数据库状态并返回持久化确认。
5. **图片查询：** 管理端通过 API 查询数据库索引；API 完成用户鉴权后签发短时下载 URL。Bucket 不开放公共读写。

数据库与 OSS 不能组成同一个事务，因此图片必须有明确的 `pending/uploaded/failed` 等状态。若对象上传成功但完成回调丢失，网关可按同一 `image_id` 重试确认；若数据库登记成功但对象未上传，API 可保留未完成状态供补传和监控，不应误报图片已归档。

#### 上传约定

以下为业务接口草案，需要云端 API 实际落实：

| 接口 | 用途 | 成功语义 |
|---|---|---|
| `POST /v1/measurements:batch` | 批量提交测量记录 | 逐条返回接收结果；以 `measurement_id` 幂等 |
| `POST /v1/images:initiate` | 登记图片元数据并申请上传授权 | 返回对象键和短时预签名 URL |
| `PUT <presigned-url>` | 上传 JPEG 到 OSS | OSS 确认对象写入 |
| `POST /v1/images/{image_id}:complete` | 请求完成校验 | 服务端校验对象、大小和 SHA-256 后确认持久化 |
| `POST /v1/devices/heartbeat` | 上报设备健康和队列摘要 | 返回服务端接收时间及只读配置版本 |

- 所有写入接口必须支持稳定幂等键；同键同内容返回既有结果，同键不同内容返回冲突，不得覆盖。
- 测量批量接口逐项返回成功、可重试或永久失败，避免单条异常阻塞整批。
- 网络错误、408、429 和 5xx 按约定退避；认证/权限/格式错误应告警并按错误类别处理，不能无限盲目重试。
- 预签名 URL 过期后重新申请授权，沿用原 `image_id` 和对象键，不重复创建业务图片记录。
- API 采用 HTTPS/TLS 和独立设备身份；日志不记录令牌或预签名 URL 查询参数。

#### 数据管理

数据库保存设备、样本、测量、图片索引、上传事件和审计记录；测量数据按设备与采集时间建立查询索引，同时保存设备采集时间和服务端接收时间。图片对象键建议采用：

```text
devices/<device_id>/YYYY/MM/DD/<sample_id>/<image_id>.jpg
```

OSS Bucket 使用私有访问。管理端经业务 API 鉴权后查询元数据并获得短时下载 URL；不得开放 Bucket 公共读写。生命周期和删除规则须在保留期确认后配置。OSS 冗余不等于误删恢复或异地备份，需按业务 RPO/RTO 另行确定版本保护、备份或跨地域复制。

管理端首期可提供设备在线/最后心跳、最近采集时间、上传积压、测量查询、图片查看、受控导出和审计。不得提供任意 PLC 写入或机械臂动作入口。监控至少覆盖 API 可用性/错误率、数据库容量和备份结果、OSS 上传失败与容量、未完成图片确认、设备心跳过期和费用异常。

#### 容量与费用

单台设备当前基线为每天 96 条测量、12 张图片。令 JPEG 平均大小为 `S_avg`、保留天数为 `D_retention`，OSS 稳态对象占用可先估算为 `12 × S_avg × D_retention`；测量数据量按 `96 × 单条记录平均大小 × 保留天数` 估算。另计数据库备份、对象版本/副本、请求、网络流量、ECS、监控和告警费用。现场 JPEG 应实测平均值、P95 和最大值；缺少地域、存储等级、保留期和流量单价时不作金额承诺。

#### 实施与验收

1. 盘点 ECS、网络入口、安全组、数据库、OSS、域名/TLS、地域、备份和费用。
2. 验证 API 设备认证、测量幂等、图片预签名上传、URL 过期重签、SHA-256/大小校验和权限隔离。
3. 演练 API 超时但服务端已提交、对象已上传但完成回调丢失、数据库恢复、OSS 误删恢复和设备凭据撤销。
4. 验收服务端查询结果与网关记录一致，重复请求不产生重复数据，监控告警和恢复流程可用。

#### 数据库选型

当前数据规模下，优先评估团队熟悉的托管 PostgreSQL 或 MySQL。单台设备基线约每天 96 条测量、12 张图片索引，普通关系型数据库即可支持常规查询；是否选择具体产品，应看现有资源、团队维护经验、备份恢复能力和费用，而不是仅因数据带时间戳就引入专用时序数据库。托管数据库可减少部分底层运维，但账号权限、数据模型、备份策略和恢复演练仍由项目负责。

### 3.2 部署对比

以下三种方案比较的是**云端组件部署方式**；现场侧均使用 SQLite + 图像文件 + outbox。

#### 方案 A：ECS 全部自建

```text
网关 -> ECS 业务 API -> ECS 自建数据库
                         └-> ECS/云盘图片目录
```

API、数据库和图片都由项目团队部署和维护，可复用现有 ECS，初期组件最少。代价是数据库升级、备份恢复、图片容量、文件保护和 ECS 故障恢复均由团队负责；单实例或单盘故障会同时影响多个服务。图片下载也消耗 ECS 磁盘和出口带宽。适合原型或具备成熟自运维能力的团队，不建议把 ECS 系统盘作为生产归档。

#### 方案 B：ECS + 托管数据库 + OSS

```text
网关 -> ECS 业务 API -> 托管数据库
                  └-> OSS（预签名直传）
```

ECS 运行 API 和管理服务，关系数据由托管数据库管理，JPEG 直接上传 OSS。服务职责清晰，图片不挤占 ECS 磁盘和 API 带宽；数据库备份、扩容和 OSS 生命周期可分别配置。代价是要配置并验证 API、数据库和 OSS 之间的权限、网络、状态一致性和费用；ECS 上的 API 仍需设计备份与故障恢复。**这是当前项目生产首版的推荐组合**，前提是现有 ECS 适合对外提供受控 HTTPS 服务，且云管理员可提供所需数据库和 OSS。

#### 方案 C：托管平台 + 托管数据库 + OSS

```text
网关 -> 托管 API/容器平台 -> 托管数据库
                         └-> OSS
```

API 运行在托管容器、Serverless 或其他应用平台，数据库和图片分别使用托管服务。平台可能提供实例替换、发布管理和扩缩容能力，适合设备、查询负载或可用性要求增长的场景。代价是平台绑定和学习成本更高，网络、日志、发布与故障排查更复杂；低流量单设备场景未必有收益。当前不作为首版默认方案，除非项目已有成熟的平台基础或明确的高可用要求。

#### 综合比较

| 比较项 | A：ECS 全部自建 | B：ECS API + 托管数据库 + OSS | C：托管 API + 托管数据库 + OSS |
|---|---|---|---|
| 初期部署 | 最快，复用 ECS | 中等，需配置托管数据库和 OSS | 较慢，需适配应用平台 |
| 首期实现复杂度 | 低 | 中 | 中高 |
| 运维责任 | 集中由项目团队承担 | API 自运维，数据库/对象存储部分托管 | 应用平台和数据服务部分托管，平台技能要求较高 |
| 图片存储与扩展 | ECS/云盘容量和备份自行管理 | OSS 对象存储，按对象管理 | OSS 对象存储，按对象管理 |
| 数据库备份恢复 | 项目自行搭建和演练 | 使用托管能力并由项目验证恢复 | 使用托管能力并由项目验证恢复 |
| 故障影响范围 | ECS 故障可能同时影响 API、数据库和图片 | ECS API、数据库、OSS 故障域相对分开 | 应用平台、数据库、OSS 相对分开，仍依赖各服务可用性 |
| 成本特点 | 云资源种类少，运维投入和单机资源集中 | 成本分项清楚，增加托管服务费用 | 平台与调用成本更多，需按实际负载测算 |
| 适用场景 | 原型、临时验证、自运维能力强 | **当前生产首版推荐** | 已有平台基础或后续规模化/高可用 |

#### 推荐方案

推荐方案 B：**ECS 运行业务 API，托管关系型数据库保存测量和索引，OSS 保存图片；现场网关以 outbox 可靠补传。** 该组合避免把单台 ECS 磁盘当作图片归档和数据库唯一副本，同时保留 ECS 部署业务接口的灵活性。选型前仍需确认现有 ECS 规格、网络入口、安全组、数据库和 OSS 资源、地域、保留期、备份恢复目标及预算；若只做短期原型，可先用方案 A，但应明确其生产化迁移和备份责任。


## 4. 待确认事项

1. **现有云资源：** ECS 规格、操作系统、网络和安全组；是否已有可用的 HTTPS API、数据库、OSS bucket、域名及测试环境。
2. **服务托管方式：** 是否采用推荐的托管数据库 + OSS；若暂用 ECS 本地磁盘存储图片，需确认备份、恢复和容量责任。
3. **数据管理策略：** 测量数据和图像的保留期限、备份要求、删除策略，以及本地上传缓存清理规则。
4. **接口与设备身份：** API 格式、幂等规则、图像上传和校验协议、设备认证方式，以及凭据轮换与撤销流程。
5. **非功能要求：** 可接受的云端恢复目标、告警责任人、预算和地域/合规要求。
6. **样本关联规则：** `sample_id` 由操作员、PLC、网关还是云端生成；一张图像关联单次测量还是一段测量窗口。
7. **数据质量与时间：** 重量/温度/湿度单位、有效范围、异常值处理、PLC 时间戳能力及允许的设备时钟偏差。
8. **上传性能与留存：** 现场 JPEG 的 P95/最大值、4G 可用上行速率、最长离线目标、补传完成时限及流量预算。
9. **云端可用性目标：** API/数据库/OSS 的可用性要求、备份频率、RPO/RTO、故障责任方和恢复演练周期。
